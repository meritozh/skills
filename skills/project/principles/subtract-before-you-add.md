# Subtract before you add

Apply when you plan an addition, a refactor, a rewrite, or a change to a doc or a skill.

- Remove first, then build: dead code, unused options, redundant checks, stale references, a stub with nothing in it.
- Make the smallest change that solves the problem. Fewer lines beat an elegant layer.
- Decide each thing once, in one place, and pass the result on.
- Build for the use you see, not for a case nobody has.
- Leave what you touched simpler, or at least no more complex, than you found it.

The test: can a line, an option, a step, or a sentence go without changing a decision? Then it goes.
