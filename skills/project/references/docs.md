# Docs

`docs/` holds the current state of the work, not a history of changes. Categories are `idea`, `feature`, and `design`. One subject is one file: `docs/<category>/<slug>.md`.

`slug` is lowercase and hyphenated. Update the existing file for that subject. If more than one file is the same subject, ask which to update. If none exists, create one. Do not add a dated sibling, a changelog, or a second file for the same subject.

The file states what is true now: what the idea, feature, or design is, and what it is not. Replace statements that are no longer true. Do not append how it changed, and do not write a plan (goal, steps, or a list of future work).

The current state must be allowed by the project-status principle for breaking changes and persisted data.
