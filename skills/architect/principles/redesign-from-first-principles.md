# Redesign from first principles

Apply when a new requirement meets an existing design: a change to a feature, a spec, a goal's route, or a module.

- Read everything the change touches first.
- Ask what you would build if the requirement had been there from the start. Build toward that, not a patch on the old shape.
- Carry the change through every place that states the old shape: types, docs, examples, decisions, glossary.
- Think through the whole redesign, then deliver it in steps.
